# 小红书 (XHS) 签名逆向分析文档

本项目成功实现了对小红书网页版核心签名 `X-s`、`X-t` 及 `X-s-common` 的逆向还原。通过 Python 调用补环境后的 JS 引擎，能够稳定获取业务接口数据。

## 1. 核心签名体系概览

在请求小红书敏感接口时，Header 中必须包含以下字段：
- **X-s**: 核心签名，包含请求路径指纹、环境指纹。基于 JSVMP (mnsv2) 算法。
- **X-t**: 签名生成的时间戳（毫秒）。
- **X-s-common**: 辅助签名，用于校验 `X-s` 与 `a1` 的对应关系。
- **x-s-v**: 签名版本标识，建议固定为 `1.3.8`。

## 2. 逆向核心逻辑 (JSVMP)

### 2.1 算法入口
核心入口函数为 `seccore_signv2(url_param, json_data, a1)`。
其流程如下：
1. **环境同步**：将传入的 `a1` 动态注入到模拟的 `document.cookie` 中。
2. **虚拟机调用**：调用混淆后的 `window.mnsv2` 函数。
3. **封装返回**：Base64 编码并增加 `XYS_` 前缀。

### 2.2 关键点：指纹对齐
**致命陷阱**：如果 JS 沙箱环境内的 `document.cookie` 中硬编码了旧的 `a1`，而请求使用了新的 `a1`，会导致 `-101` 错误。必须在 JS 函数执行前动态同步最新的 `a1`。

## 3. 常见风控绕过技巧

### 3.1 URL 编码一致性
- **坑点**：`xsec_token` 末尾的 `=` 会被 `requests` 库自动转码为 `%3D`。
- **对策**：生成签名必须基于转码后的 `%3D` 路径，且请求时需直接请求完整 URL 避免二次转码。

### 3.2 隐藏的 `web_session`
- **坑点**：`web_session` 带有 `HttpOnly` 标记，脚本无法通过 `document.cookie` 获取。
- **对策**：必须从浏览器的 Network 面板中提取完整的 Request Header Cookie。

## 4. 环境依赖与运行

### 4.1 环境要求
- **Node.js**: 执行加密 JS。
- **Python 3.x**: 业务调度。
- **JS 库**: `npm install crypto-js`。

### 4.2 文件说明
- `xhs_main_260411.js`: 核心逆向引擎。
- `main.py`: 签名调用封装。
- `test_request.py`: 集成测试脚本（包含完整请求逻辑）。
